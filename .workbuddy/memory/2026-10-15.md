## 14:42 「感觉不对」逐层诊断（用户：玩着觉得不贴合设想，挂机没意义）

### 用户设想的 fun 模型 = 旅行青蛙
- 人不在时宗门**自动运转**；人只偶尔**提方向**；少数几代想指导时再**亲自指导**。
- 「派弟子出去游历→看经历/看生平→用资源升宗门→招新再派」是**情感循环**，不是操作循环。

### ⚠️ 纠正了上一版误读
- 我一度把「派遣/接代自动化」当成偏差 → **错**。用户**就要**自动化（旅行青蛙式）。
- 真实偏差收窄为：**自动运转有了，但自动发生的事没变成"能认识和牵挂这个弟子"的材料。**

### 具体偏差（旅行青蛙模型下）
1. 经历不可见：你"看经历"的载体是 HUD 数字+尸体密度，战斗过程不可观看（零操作没错，但无「见闻」）
2. 回报物不可牵挂：编年史是事件 log（第N代：突破X/掉Y/死老），是统计不是「这一代独有的故事/相册」
3. 「提方向」无情感重量：调 BD/选秘境是数值操作，没和某代弟子性格/命运绑
4. 「偶尔亲自指导」零入口：R180 议事堂只 BD 倾向，无「指导某一代」钩子

### 结论
- 循环结构对了（多世代/传承/搜打撤/编年史都已在），**叙事包装错了**：弟子每次出门-回来没产出「这一趟属于他」的可见记忆 ⇒ 记不住任何一代 ⇒ 挂机像看数字涨。
- 方向候选（用户让先商讨、代码不动）：A 补「寄回物」叙事层(最小) / B 给提方向情感重量 / C 加亲自指导可选钩子 / D 先出纸面或风格小样。

## 2026-10-16 18:1x ★ R70：修"有来有回" —— 低压段（R216 的解法）

用户："1 修'有来有回' 然后你那个 --app 是怎么个实现 试试呢"

### 🔍 先搞清 thresh 能不能动
`thresh = (THRESHOLD_R(10)+…) × tankiness`，标定的是**【危险模型·25 秒恒定】**
（excess=1 恰好撑 `SURVIVE_SECONDS=25` 秒）⇒ **不能动 thresh**，且它随防御力长大
⇒「越强越不会挨打」。⇒ 做法：**在高压曲线下面挂一条低压段，用 max() 取大**：

```js
const _exHigh = threatW - st.thresh;                    // 原曲线，一个字不动
const _dLow   = max(0, threatW - thresh*LOW_GATE) / (thresh*(1-LOW_GATE));
const excess  = Math.max(_exHigh, _dLow * LOW_MUL);     // ★ 高压段永不被改
```
为什么 `max()` 不是相加：**相加会改高压配平**；`max()` 保证 `_exHigh ≥ LOW_MUL` 后低压不参与
（有行为断言钉死："威胁 = thresh+5 ⇒ excess 恰为 5"）

### ⚠️⚠️ 一个漏了就白修的坑（第一版真踩了）
守卫原是 `if (threatW > st.thresh)`。**我只改了 excess 算法、忘了这个守卫**
⇒ 炼气期 `threatW(10.8) > thresh` 仍为假 ⇒ 整块走不到 ⇒ **依旧 0%**。
⇒ **守卫必须一起放宽到 `thresh × LOW_GATE`**。

### 📊 LOW_MUL 必须按实测标定（理论换算不可信）
理论（excess=1 ⇒ 撑 25 秒）**比实际保守得多**（威胁在波动、怪只在部分时间进圈）。
第一版 0.08 ⇒ 实测一局只掉 5% 血 ⇒ 飘字 "-1"，等于没修。
**实测（炼气期 · 每档 3 轮平均）**：

|---|---|---|---|---|
| 0.5 | 14% | 129 | 0/3 | 541 |
| **1.5（选中）** | **76%** | **179** | **0/3** | 573 |
| 3.0 | 287% | 270 | 3/3 | 600 |
⇒ 1.5 = 血条明显波动但**不死**。嫌疼就调小这一个数（R220 待 playtest）
