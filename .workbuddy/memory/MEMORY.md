## 法宝 · 反噬（R74 收口，改法宝前必看）
- **法宝不再"每局每件 1 次"** → **可重复催动 + 逐次变长冷却**：
  `下次可催动 = GF.swingW + min(P.FABAO_CD_BASE(20) × 2^已催动次数, P.FABAO_CD_MAX(120))`
- **反噬**（本局累积、跨法宝共享、**卸下法宝不清零**）：每层 出手 −1% · 承压 +6%
  → **满 8 层（`P.FABAO_BL_MAX`）⇒ 走火入魔 ⇒ 本局立即结束回宗门**
  ⚠️ **不算阵亡**（弟子活着）：`endRun(false, 'backlash')` 必须排掉 `endDisciple`
- **本源 `P.ORIGIN_PER_KILL = 0.22`**（一局 ~180）。原来的 1（674/局）之所以白给，
  根因是【支出被"每局 1 次"锁死在 45】—— 改重复催动之后本源才成为硬约束（A15 收口）
- **止损杠杆 = 卸下法宝**（面板「反噬 N/8 · ⚠️ 危险」+ 战场状态条同步）
- ⚠️ **走火入魔不能直接 endRun**：那段在 `step()` 出手循环深处，半路 `return` 会跳过
  本次出手剩下的收尾 ⇒ **立旗 `G._backlashDown`、由 `tick()` 开头收**
- ⚠️ **`fbTriggered` 读的是 `ctx.swings` 不是全局 `GF.swingW`**：
  测试里不传 `swings` 会拿到默认 0 ⇒ "冷却结束"那次也判成冷却中（第一版测试就这么错的）
- ⚠️ **出手频率必须有下限（0.4）**：防以后调大 `FABAO_BL_FREQ` 把出手压成 0（整局卡死）
- 实测（`node _tools/fabao_balance.js 18`，交错跑）：正常玩 走火入魔 **5%** ·
  一直烧（节拍型法宝）**85%** ⇒ **机制成立**
  ⚠️ 参数（1% / 6% / 8 层）是**第一版，仍待 playtest**（R230）

## 桌面窗口壳 / 打包（R73 收口，改启动方式前必看）
- **`_shell.py` = 桌面窗口壳**（pywebview / WebView2）：`frameless=True` **真无边框** +
  老板键 `Ctrl+Alt+H`（`ShowWindow SW_HIDE`，连任务栏一起消失）+ 置顶 `Ctrl+Alt+P` + 退出 `Ctrl+Alt+Q`
  · 拖动走 `WM_NCLBUTTONDOWN + HTCAPTION`（让系统跑移动窗口的模态循环）
  · 缺 pywebview ⇒ **自动退回** `_launcher.py` 的 Edge `--app` 窗口
  · 自检：`python _shell.py --selftest`（进程内验无边框/注入/隐藏/是否还在打）
- **`启动.bat` 默认走窗口壳**；`原型/打包exe.bat` = 一键打 exe
- **单文件 exe 已跑通**：`秘境录.exe` **12.6 MB**，**不需 Python / 浏览器**（发布包里）
  ⚠️ 打包后 `__file__` 是 `_MEIPASS`（临时解包目录）⇒ `ROOT` 必须改认 `sys.executable`
- ⚠️⚠️ **`easy_drag=True` 会吃掉页面所有点击**（它插的是全局 `mousedown` 监听）⇒ 必须关掉
- ⚠️ **ctypes 调 `SetWindowPos` 必须声明 `argtypes`**：`HWND_TOPMOST = -1` 不声明会按 32 位传
  ⇒ 无效句柄、**静默失败**（实测返回 0）
- ⚠️ **`ShowWindow(SW_HIDE)` 不改变 `document.visibilityState`**（实测仍 `visible`）
  ⇒ 隐藏**不触发**"离开结算"；但**隐藏期间照样全速跑**（实测 6 秒 +12 击杀）⇒ 对摸鱼是好事
- ⚠️ **全局热键先到先得**：`RegisterHotKey` 返回 0 就是被占了（本机 `Ctrl+Alt+T` 被占）
  ⇒ 配一串候选键，并回报真正生效的那个
- ⚠️⚠️ **`.gitattributes` 必须有**：`core.autocrlf=input` 会把 `启动.bat` 在库里存成 **LF**，
  而 LF 批处理在 Windows 上会出怪问题 ⇒ 用 `*.bat text eol=crlf` 钉死

## 远程弹道（R71 收口，改远程观感前必看）

## 承压 / 危险模型（R70，改"挨打"相关前必看）
- **`thresh` 不能动**：它标定**【危险模型·25 秒恒定】**（excess=1 恰好撑 `SURVIVE_SECONDS=25`）
  且随**防御力**长大 ⇒「越强越不会挨打」→ 这就是"没有来有回"的根源
- 要加压力走 **低压段**：`excess = Math.max(threatW - thresh, _dLow * LOW_MUL)`
  ⚠️ 必须 `max()` 不能相加（相加会改高压配平）
  ⚠️ **守卫也要一起放宽**：`if (threatW > st.thresh * LOW_GATE)` —
     只改 excess 不改守卫 = **修了等于没修**（第一版真踩）
- `LOW_MUL = 1.5`（**实测标定**：掉血 76% / 扑击 179 / 0 阵亡；0.5 ⇒ 才 14%、3.0 ⇒ 必死）
  ⚠️ **理论换算不可信**（威胁波动、怪只在部分时间进圈），必须实跑量

## ⚠️⚠️ 两个时钟（最容易出错的地方，改任何"时长"前必看）
- **游戏时钟 = 真实时间 × 2.33**（`tick()` 每次推进 0.5 游戏秒）。实测口径。
- **数值/配平**用游戏时间（`G.t`、`P.RUN_SECONDS`、`actFreq`、寿元…）
- **表现层**（特效/飘字/延迟音/死亡消散）必须用**真实时间**（`Date.now()`）——
  因为 **CSS 动画走的就是真实时间**。R61/R62 我用了游戏秒 ⇒
  元素存活期只有动画的 43% ⇒ **特效被截断**（用户："又短又快"）。
  ⇒ 不变量：**JS 元素存活期 ≥ CSS 动画时长**（已有断言盯）
- **VFX 里的 `*_MS` 常量一律是真实毫秒**：弧光 320 / 死亡消散 420 / 技能 900 / 横幅 1150
- ⚠️ **顿帧会让"寿命"和"动画"再次错位**（R71 补的第二条路径）：
  顿帧靠 `#battleWrap.freeze` 的 `animation-play-state:paused` 停 CSS 动画，
  而寿命按 `Date.now()` 算 ⇒ **动画没播完元素就被删**。
  ⇒ `vfxTick` 累计 `G.fxFreezeMs / G.fxFreezeAt`，每个特效按**出生之后**冻掉的部分扣减
  （`v.froze0` 是出生时的累计值；**不能直接扣总量**，那会让之后出生的特效赖着不走）。

## ⚙️ 运行节奏（会解释很多"为什么看不见"）
- **`tick()` 每 ~215ms 才跑一次**，每次 `for(s<5) step(DT=0.1)` ⇒ 推进 **0.5 游戏秒**
  ⇒ **逻辑更新率只有 ~4.6Hz**，游戏秒 = 真实秒 × **2.33**
- ⇒ 一切"移动"都靠 **CSS 过渡**抹平；**"时长"比"位移量"更决定观感**
- ⇒ 改任何表现时长：要么用真实时间（`Date.now()`），要么给它折算（×2.33）
