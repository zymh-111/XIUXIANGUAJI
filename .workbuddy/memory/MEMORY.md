## 战斗表现层（R61 收口，改战斗观感前必看）
- **节拍**：`P.CADENCE = 2` —— 出手间隔 ×2 且【每刀伤害 ×2】⇒ **DPS 与一局收益不变**。
  ⚠️ 按【出手次数】计的机制一律用 **`GF.swingW`（加权出手数，每次 +CADENCE）**，别用 `GF.swings`：
  功法主动技 `cd:'swing'`（10/10/12/15/20）· 法宝木灵回春每 25 次 · 凌波微步 N 次
- **表现层三队列**（数值瞬时结算，只管"让玩家看见过程"）：
  `G.vfxq`（弧光/弹道）· `G.dmgq`（延后跳字）· `SFX_Q`（延后命中音）
  入口：`pushDmgFx()` / `sfxDelay()` / `vfxTick()` / `vfxRender(arena)`
- **武器手感身份**：`sword/blade/spear → arc 弧光` · `bow → arrow` · `staff → orb`
- **死亡消散**：怪从 `field` 删除后 DOM 还留 `VFX.DIE_DUR`(0.26s) 做碎裂 ⇒ 行为层零改动
- **法宝/功法特效**：`SKILL_ARCH`（ring/rays/flash 三类原型）× 五行色 + `.vfx-name` 名字横幅
  · `FABAO_ARCH` 是法宝→原型的唯一映射（漏配=静默无反馈，有断言）
- **顿帧**：`hitstop(ms)` 设 `G.freezeUntil`（**真实时间**）。⚠️ **只冻表现、绝不冻游戏时钟**
  （冻时钟会改 DPS 与一局时长）。四档：暴击 55 / 精英 90 / 技能 110 / Boss与突破 150
- **几何命中**：`hitCandidates(st)` 是唯一判定入口 —— 近战按 `WPN_HIT` 的**扇面角**、
  远程按**溅射半径**。扇面角就是 `WEAPONS` 里 desc 的落地（剑宽/枪窄/杖溅射大）
  · 弧光的 `--a`/`--sz` 必须与判定同源（改了判定要同步改表现，有断言盯）
  · 调扇角用 `node _tools/reach.js <武器id>`
- **量手感用 `node _tools/pace.js`**：出手间隔 / 每秒击杀 / 飘字密度 / 单刀并发数 + 可辨识性判据
  （判据：看清一次打击需 ≥250ms；单刀同帧结算 ≥3 个目标就开始糊）

## 离开结算（R67，改离线/后台收益前必看）
- **`settleAway(真实秒, 效率, 封顶)` 是唯一公式** —— 离线与后台都调它（两套口径必然漂）
- ⚠️ **两套效率常量，别混用**：
  `OFFLINE_EFFICIENCY = 0.12` → 只给【传承/交接】（`legacyQiValue`/灵气封存，游戏秒口径自洽）
  `AWAY_EFFICIENCY = 0.048` → 给离开结算（真实秒口径；×2.5 才等效于 0.12）
  改错就是**静默**削掉某一条收益 2.5 倍（R67 我差点犯）
- 后台：`BG_EFFICIENCY=0.5`（门槛 5s，封顶 1h）。设计原则 = **在线（看打）效率 100%，
  离开打 5 折**：低了"看着打"没价值，高了玩家没理由开着
- ⚠️ 平台决策已定：**不换平台**（桌面/小程序会弄坏"上班摸鱼"场景），
  后台节流靠"离开=结算"绕开，不指望 tick 在后台跑

## ⚠️⚠️ 两个时钟（最容易出错的地方，改任何"时长"前必看）
- **游戏时钟 = 真实时间 × 2.33**（`tick()` 每次推进 0.5 游戏秒）。实测口径。
- **数值/配平**用游戏时间（`G.t`、`P.RUN_SECONDS`、`actFreq`、寿元…）
- **表现层**（特效/飘字/延迟音/死亡消散）必须用**真实时间**（`Date.now()`）——
  因为 **CSS 动画走的就是真实时间**。R61/R62 我用了游戏秒 ⇒
  元素存活期只有动画的 43% ⇒ **特效被截断**（用户："又短又快"）。
  ⇒ 不变量：**JS 元素存活期 ≥ CSS 动画时长**（已有断言盯）
- **VFX 里的 `*_MS` 常量一律是真实毫秒**：弧光 320 / 死亡消散 420 / 技能 900 / 横幅 1150

## ⚙️ 运行节奏（会解释很多"为什么看不见"）
- **`tick()` 每 ~215ms 才跑一次**，每次 `for(s<5) step(DT=0.1)` ⇒ 推进 **0.5 游戏秒**
  ⇒ **逻辑更新率只有 ~4.6Hz**，游戏秒 = 真实秒 × **2.33**
- ⇒ 一切"移动"都靠 **CSS 过渡**抹平；**"时长"比"位移量"更决定观感**
- ⇒ 改任何表现时长：要么用真实时间（`Date.now()`），要么给它折算（×2.33）

## 进度条（R66，改功法/法宝的"攒进度"显示前必看）
- `gfProgress(g)` / `fbProgress(f)` 是**唯一真相源**，返回 0~1（null = 不该画条）
- ⚠️ **必须与真实触发同源**（gfReady 的字段 / fbTriggered 的 ctx）——
  不同源就是"进度条骗人"，有断言抠函数体检查
- 两处：战场 `#skillBar`（弟子脚下，最多 3 条×3px）· 列表 `.pg`（2px 贴行底，精确值放 title）
- ⚠️ **结构变了才重建，每帧只改 width**（`box._sig` 签名比对）——
  每帧 innerHTML 是 R61 踩过的坑（元素反复销毁 ⇒ 事件丢失）

## ⚠️ 工具坑（R61 踩过）
- **用 Edit 插 CSS 时，`old_string` 只取"要替换的那一行"** —— 把前一行包进去会连带删掉
  相邻规则（R66 实际删掉过 `.mob.hit`，受击变亮失效）。
- **不要用 Python 文本模式写项目文件**（`io.open(p,'w')`）—— 它会把**整份文件的换行符**从 LF 转成 CRLF，
  进而让按字面 `'\n'` 切的测试锚点静默失配。用 **Edit 工具**改。
- **验证交互/音效必须 `shot.js --gesture`** —— Chromium 自动播放策略要求用户激活，
  而 `el.click()` 是合成事件不给激活。
- **游戏时钟比真实时间快 ~2.4×** —— 用真实 `setTimeout` 卡 0.2s 的特效时窗会测不到。
- **验证"某元素被冻结/被重建/是否还在"必须【持有元素引用】** —— 每次重新 `querySelectorAll`
  可能拿到另一个元素（R62 实踩）；更坑的是**按 class 数数量**（R63）：战斗中一直有新特效、
  数量恒定 ⇒ 完全测不出"被提前删除"，还差点得出"修复无效"的错误结论。

## 音效线（R60 收口，改音效前必看 `音效清单与映射.md`）
- 素材：`原型/游戏/assets/音效/*.mp3` **113 个 / 0.73MB**（源 `美术资源/05_音效/` 16.1MB，转码 22.3×）
- 管线：`原型/游戏/_tools/audio_pack.py`（混单声道 + 统一峰值 + **不重采样** + MP3）
- 代码入口：`sfx(key)` / `SFX_FILES`（事件→文件）/ `SFX_CFG`（音量·间隔·概率）/ `SFX_FORM`（形态→死亡音）
- **四条硬约束**：① **默认关闭**（摸鱼场景！开关在右上角，存 localStorage）
  ② **用 `<audio>` 不用 Web Audio**（发布包是 file:// 双击打开的，fetch/decodeAudioData 被 CORS 拦）
  ③ **必须节流+概率**（挂机每秒 1~2 击杀，不处理是机关枪）
  ④ **音量分层**（战斗音 0.16 级 / 里程碑 0.65~0.85）
- ⚠️ **验证音效必须用 `shot.js --gesture`** —— Chromium 自动播放策略要求用户激活，
  而 `el.click()` 是合成事件不给激活 ⇒ 不用 --gesture 会测出满屏 NotAllowedError（误判）
- ⚠️ **加新敌人形态必须同步加 `SFX_FORM`**，否则那种怪死时没声（有断言盯着）
