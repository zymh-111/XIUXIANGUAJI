## 🔴 踩过的坑（按发生顺序）

### 1. PowerShell 读 UTF-8 会把中文注释的行尾吃掉
`Get-Content -Raw` 按 GBK 解码 UTF-8 文件 ⇒ 中文注释的多字节序列把换行吃掉
⇒ 多行合并成一行 ⇒ `nginx: "location" directive is not allowed here`

**修**：`[System.IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)` + 写回时 LF 换行。
**更好的做法**：远程脚本/配置里**只用英文注释**。

### 2. `ssh root@host $cmd` 的引号会被 PowerShell 搞坏
多层引号 + `$(...)` 会被本地展开。

**修**：脚本写成文件 → `Get-Content file -Raw | ssh ... "bash -s"`。
⚠️ 但 heredoc 里有中文仍可能出问题 ⇒ 脚本内也用英文。

### 3. apt 被 `unattended-upgrades` 锁住 200 秒
首装时它正在升级 200+ 个包（含 libc6 / systemd）。
**绝对不要杀**（会搞坏系统）。修：轮询等锁，或做成后台任务。

### 4. `sslip.io` 的 SNI 被干扰 ⇒ HTTPS 只有 1/10 能连
实测（境内 → 境内服务器）：

| SNI | 成功 |
|---|---|
| IP | **10/10** |
| `8-137-167-162.sslip.io` | **1/10** |
| `8-137-167-162.nip.io` | 6/6 |

⇒ `sslip.io` 这个域名被盯上了（它本来就常被用来绕域名封锁）。

### 5. `nip.io` 的证书签不下来
`certbot --webroot` 两次都失败：
```
Fetching http://8-137-167-162.nip.io/.well-known/... : Connection reset by peer
```
但用境外 fetcher（web_fetch）取同一个 URL **是 200**。
⇒ 说明 Let's Encrypt 的验证节点到这台服务器的路径上被 reset。
**未解决**，绕开方案见下。

### 6. 我一度把 HTTP 全 301 到 HTTPS ⇒ 游戏直接打不开
HTTPS 90% 被 reset，而 HTTP 全跳转过去 ⇒ 等于不可用。
**修**：HTTP 直接服务游戏（不跳转），HTTPS 保留给能连上的客户端。
（换成真域名后已改回正常的 301 跳转）

### 7. ★★ Service Worker 一次性并发 257 个请求 ⇒ 卡在 installing ★★
`sw.js` 里原来用 `Promise.all(files.map(...))` 缓存全部素材。
**实测**：30 秒只缓存了 **55 / 257**，SW 一直 `installing`、`active=false`
⇒ 手机上会更糟（连接数被限流）。

**修**：改成 **有限并发 6 条 + 单请求超时 12 秒**
- 任何一个文件失败/超时只跳过它，不阻塞整体安装
- 缓存版本升到 `v2`

**验证（同一 profile 连跑两次）**：
```
regs 1  active=true  waiting=false  installing=false
controller=true
caches mijinglu-v2 = 259 files
```

> ⚠️ 这个坑只有在**真机/真实网络**下才暴露 —— 本地 localhost 测不出来（太快了）。

### 8. 真域名一到位，前面 4/5 的问题全没了
换成 `doublemoon.com.cn` 后：
- SNI 干扰消失（HTTPS 10/10，而 sslip.io 是 1/10）
- Let's Encrypt 验证一次通过
⇒ **"免费蹭域名"省的那点钱，全赔在排查时间里了。**

### 9. ★★ 子域名的证书签不下来（LE 多节点验证被拦）★★
给 `game.doublemoon.com.cn` 签证书，失败 **4 次**，都是 `403`。

**关键证据**（服务器 access.log）：
```
23.178.112.210 GET .../acme-challenge/tHjj...  200 87   ← 我们返回了正确的 token
23.178.112.210 GET .../acme-challenge/iE0G...  200 87   ← 又一次正确
23.178.112.107 GET .../acme-challenge/YBaw...  200 0    ← nginx 插件版返回空
23.178.112.212 GET .../acme-challenge/tqQe...  200 0
```
⇒ **我们的服务器返回了 200 + 正确的 87 字节**，但 LE 报 403。
⇒ LE 用**多个验证节点**；其中某些节点在到达服务器之前就被中间设备拦了。
   这是网络层的问题，**服务器侧无法解决**。

**排查过程中排除掉的可能**：
- ✅ 不是文件权限（root 644 → 200；root 600 → 403，certbot 写的是 600）
- ✅ 不是 webroot 路径（`/var/www/acme` 正确）
- ✅ 不是 nginx 配置（`Host: game.` 本地取 200）
- ✅ 不是 DNS（通配符 `*` 已生效，权威+公共都解析到 8.137.167.162）
- ✅ 不是 nginx 插件（它也 403，而且它返回空 body）

**最终方案：改用路径 `/game/`**，复用现有 `doublemoon.com.cn` 证书。
好处：立即可用、同源（存档不丢）、和另一会话的 `/fate/` 模式一致。
代价：URL 是路径；以后想换子域名会换 origin，存档要搬一次。

> 如果以后一定要子域名：需要走 **DNS-01 验证 + 阿里云 AccessKey**（自动增删 TXT 记录），
> 或者手动加 TXT（每 90 天一次）。**HTTP-01 这条路在这个网络环境下不可靠。**

## 下一步：注册域名（这是正解）

`sslip.io` / `nip.io` 这类"零成本域名"都有被干扰的风险。
**注册一个真域名能同时解决 SNI 干扰和证书签发问题。**

### 但大陆服务器有个坎：ICP 备案

域名指向**大陆服务器**提供服务，按法规需要 ICP 备案：

| | 买域名 + 备案 | 买域名 + 非标端口 | 只用 IP（现状） |
|---|---|---|---|
| 费用 | ¥10~70/年 | 同左 | 0 |
| 等待 | **1~3 周**（阿里云初审 + 管局） | 立即 | 立即 |
| URL | `https://xxx.top` | `https://xxx.top:8443` | `http://8.137.167.162` |
| HTTPS | ✅ | ✅ | ⚠️ 不稳 |
| 添加到主屏 / 离线 | ✅ | ✅ | ❌ |
| 风险 | 无 | 严格说仍未备案，有被查的可能 | 无 |

**建议**：买域名 + 提交备案，等备案期间先用 IP 玩。

### 域名指向这里之后的步骤（我已备好脚本）

1. 阿里云 DNS 加 A 记录 → `8.137.167.162`
2. 等 DNS 生效（`nslookup 你的域名` 能看到 IP）
3. 我执行：签证书 → 改 `server_name` → 换证书路径 → reload → 验证
   （脚本 `2_换域名重签.sh` 已经把流程写好了）
